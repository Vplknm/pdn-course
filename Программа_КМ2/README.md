Самостоятельный проект: не требует соседних лабораторных. Содержит готовое распознавание и оценку качества. Обезличивание и BERTScore относятся к КМ3 и в этот срез не входят.

## Установка

Проверено на macOS ARM64 с Python 3.12.16. Для воспроизведения рекомендуется Python 3.12. Пакеты устанавливаются только в виртуальное окружение.

```bash
cd Программа_КМ2
python3.12 -m venv .venv
source .venv/bin/activate
python -m ensurepip --upgrade
python -m pip install -r requirements-lock.txt
python check_km2.py
```

Windows PowerShell:

```powershell
cd Программа_КМ2
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe check_km2.py
```

При использовании уже установленной среды общего проекта на Mac достаточно активировать её, перейти в эту папку и выполнить `python check_km2.py`.

Для установки нужен интернет. После установки модель NER и эмбеддинги читаются из пакета Natasha; внешние API при распознавании не используются. Крупные модели BERT и torch для КМ2 не нужны.

## Метод

Natasha/Slovnet находит PER, pymorphy3 делит найденного человека на NAME, SURNAME и PATRONYMIC. Конечные списки ФИО используются только генератором синтетических карточек. Структурированные атрибуты распознаются регулярными выражениями; ИНН, карта, СНИЛС и ОГРНИП проверяются по контрольным разрядам. Конфликты диапазонов разрешаются по фиксированному приоритету и длине. Каждый токен имеет ровно один BIO-тег.

Поддерживаются 16 типов: SURNAME, NAME, PATRONYMIC, INN, PASSPORT, BANK_CARD, SNILS, OGRNIP, URL, IP, PHONE, EMAIL, MARRIAGE_CERT, BIRTH_CERT, CADASTRAL, KLADR. Обязательны для чётного варианта: SURNAME, NAME, INN, PASSPORT, BANK_CARD, OGRNIP, IP, EMAIL, BIRTH_CERT, KLADR.

## Данные

- `data/test_dataset.jsonl` — основной набор: 100 документов factRuEval2016 testset и по одной явно отделённой синтетической карточке реквизитов к каждому документу. Это не реальные реквизиты людей из статей.
- `data/synthetic.jsonl` — дополнительная проверка на 120 полностью синтетических текстах с шестью падежами и разными форматами.
- `data/source/factRuEval2016` — исходные тексты, исходная разметка `.spans` и лицензия корпуса.
- `data/provenance.json` — источник, правило выбора первых 100 файлов по числовому book_id, контрольные SHA256, seed генератора 20261120.

Границы NAME/SURNAME/PATRONYMIC исходных статей перенесены из ручной разметки корпуса. Остальные классы исходной разметки не относятся к ПДн выбранного набора и считаются O. Структурированные ПДн, которые встретятся в оригинале вне этой разметки, могут дать ложноположительные ответы; это ограничение открыто учитывается в оценке. Дообучения по этим документам не проводилось. Состав обучения готовой сторонней модели отдельно не аудировался, поэтому полная независимость от её предобучения не заявляется.

Повторная сборка без сети:

```bash
python -m pdn_course.build_dataset
```

Восстановление перезаписывает два JSONL-файла, не меняя исходные `.txt/.spans`. Нельзя считать каждую карточку отдельным реальным документом: в основном наборе ровно 100 смешанных записей.

## Метрики

```bash
python -m pdn_course.evaluate --dataset data/test_dataset.jsonl --output results/recognition_metrics.json
python -m pdn_course.evaluate --dataset data/synthetic.jsonl --output results/synthetic_metrics.json
```

`check_km2.py` выполняет тесты, сборку данных и оба расчёта, проверяет 100+ текстов, 50+ сущностей каждого класса и пороги BIO macro F1 0.80 / weighted F1 0.85.

- `bio_excluding_O` — основная токенная оценка по B/I-классам, O исключён из усреднения F1;
- `per_bio_class` — показатели каждого B/I-класса;
- `per_attribute` — показатели по атрибутам после объединения B/I;
- `attributes_excluding_O` — macro/weighted/micro по 16 атрибутам;
- `required_variant4_excluding_O` — диагностическая оценка только 10 обязательных атрибутов;
- `accuracy_including_O` — доля верных BIO-тегов с O;
- `exact_span` — дополнительная строгая проверка типа и обеих символьных границ;
- `*_errors.json` — все пропущенные и лишние/неправильно размеченные диапазоны;
- `environment` и `dataset_sha256` — версии среды и хеш оценённого файла.

Синтетический набор предназначен для регрессионной проверки форматов, а не для заявления точности на произвольном тексте. Основные выводы отчёта сделаны по смешанному набору с реальными статьями. Результаты корпусной разметки не являются официальной оценкой соревнования factRuEval: здесь другая задача, токенизация и набор типов.

## Состав проекта

`pdn_course/person_ner.py` — модель ФИО; `recognizer.py` — объединение правил и модели; `validators.py` — контрольные разряды; `generate_dataset.py` — синтетические данные; `build_dataset.py` — сборка с корпусом; `evaluate.py` — метрики; `demo.py` — интерфейс; `tests` — 13 тестов.

## Источники и ограничения

Исходный корпус: https://github.com/dialogue-evaluation/factRuEval-2016 (лицензия MIT приложена). Natasha: https://github.com/natasha/natasha . Slovnet: https://github.com/natasha/slovnet . Морфология: https://github.com/no-plagiarism/pymorphy3 .

Правила свидетельств требуют контекстной фразы «о браке:» или «о рождении:»; карта поддерживается в виде 16 цифр; телефон — российский номер с +7 или 8. Редкие фамилии, инициалы, транслитерация и омонимы могут распознаваться ошибочно. Валидная контрольная сумма не подтверждает фактическое существование реквизита.
